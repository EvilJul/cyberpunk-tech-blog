# 博客产品演进计划：统一作者工作台与发布集成

日期：2026-11-09。状态：本地实施与集成验收完成（工作区32/32、发布集成25/25），已按依赖顺序归档并同步主规格。统一工作台含 32 项任务，发布集成含 25 项任务；当前完成情况以各 change 的 tasks.md 为准，运行结果见 [实施验收](implementation-verification.md)。本文保留规划时的基线、决策与依赖顺序，不代表已发布到生产。

## 1. 产品决策与边界

默认使用一个网站地址、一个应用服务与一个公开端口。首页与阅读页保持访客体验；站长从首页登录，在原页面出现写作/编辑快捷入口，完整管理集中到 `/studio`。同一进程提供静态构建与 API；开发期 Vite 热更新可以保留，但使用者无需分别打开管理端口。独立备份任务不构成第二套网站。

采用 React 作者工作台承接旧管理端能力，分阶段迁移，最终默认启动不再要求 3033 服务。文章、分类、标签、主题、图片、设置、日志功能先盘点后迁移；评论审核需要从现有占位实现成可用流程。现有后台不原封不动嵌入首页，不维护两套长期编辑流程。

第二项把博客建设为未来内容中台的发布目标：中台持有专用集成密钥，调用版本化 API 发布内容。中台的平台适配器与跨平台分发逻辑留在中台。两项共用文章业务服务，避免工作台与外部接口产生两套发布规则。

第三项已确认优先目标是第一眼的视觉效果。布局、配色、字体、背景和动效单独讨论；本轮不加入项目库、知识图谱等内容功能，也不自动重做已有主页。

## 2. 当前基线与缺口

已存在 React 阅读站点、JWT 管理路由、独立静态管理端、SQLite 文章与评论、主题设置、图片上传、备份与隔离测试。公共服务本身已能托管构建产物，双入口主要来自独立管理端与开发流程。

现有缺口包括：没有首页登录与作者态；浏览器依赖 sessionStorage JWT；首次用户初始化缺少面向安装者的向导；评论管理仍为占位；文章缺少可隔离的编辑工作副本与并发版本；无独立集成身份、文章来源映射、幂等请求记录及正式 API 契约。背景与卡片最近的修复必须纳入后续回归基线。

## 3. 变更 A：统一作者入口和工作台

对应 `openspec/changes/archive/2026-11-09-unify-author-workspace/`。

### 用户路径

1. 已有站点：保留当前站长与密码，首页进入 `/login`；登录后回到安全的站内原页面，导航出现“写文章/工作台”。
2. 全新安装：引导安装者用本机生成的一次性初始化凭据创建首位站长；初始化完成后入口关闭，不能被陌生访客抢占。
3. 写文章：进入 `/studio/editor/new`（最终以该 change 规格路由为准），输入 Markdown、标题、摘要、分类和标签，上传图片、预览并保存草稿；明确区分“保存”和“发布”。
4. 改已发布文章：公开页点击“编辑”进入工作副本；保存过程不影响访客，确认发布才更新公开版本。
5. 管理内容：文章列表支持草稿/已发布筛选、分页和编辑；评论提供待审核、通过、拒绝、删除与关联文章入口。
6. 管理站点：集中调整基础信息、外观、图片、账号与集成，保存有成功/失败反馈；界面不展示实现日志或无用配置。
7. 退出或会话失效：清理作者态，保护未保存内容，不能因 401 丢掉正在写的正文。

### 实施工作包

| 工作包 | 交付 | 通过条件 |
| --- | --- | --- |
| A0 能力盘点 | 旧管理功能、端口、接口、账号和数据迁移对照 | 现有功能均有去向，已知占位明确补齐 |
| A1 身份与安装 | 单次初始化、会话、退出、修改密码、作者态与路由保护 | 已有账号不重建；陌生请求不能抢注或操作后台 |
| A2 文章服务 | 工作副本、发布快照、版本条件、事务化保存发布 | 保存草稿不改公开内容；冲突不覆盖；失败可重试 |
| A3 写作体验 | 编辑器、媒体插入、预览、草稿恢复、发布确认 | 从首页写文发布并回到公开文章完成闭环 |
| A4 完整管理 | 分类标签、评论审核、外观设置、账号与日志 | 原能力迁移可用，审核通过后访客才可见评论 |
| A5 单入口交付 | 单服务路由、子路径、默认容器和旧入口退场 | 同一地址可阅读/登录/管理，无需打开 3033 |
| A6 回归与切换 | 浏览器、权限、备份恢复和升级文档 | 旧文章 URL、背景、卡片、RSS/SEO 与数据保持正确 |

会话使用可撤销的不透明随机标识，浏览器通过 HttpOnly Cookie 携带；生产启用 Secure，状态修改使用 CSRF 令牌与来源校验。后台内容响应禁止共享缓存与索引。旧 JWT 接口的过渡期和退出条件在 change 中明确，不能直接断开未来可能已有的调用方。

## 4. 变更 B：稳定发布 API 与集成管理

对应 `openspec/changes/archive/2026-11-09-add-publishing-integrations/`，实施依赖 A 的文章服务、版本字段、工作副本与浏览器会话约定。

### 中台接入路径

1. 站长在“工作台 → 集成”创建集成，选择读取、写草稿、发布、上传权限，获得只显示一次的密钥。
2. 中台先查询连接与权限，再携带来源文章编号同步到博客；请求中保存稳定的 external_id。
3. 首次同步创建草稿，后续同步更新同一篇工作副本。需要发布时调用明确的发布动作。
4. 请求超时可携带同一幂等键重试；操作与返回结果保持一致，不重复建文或重复发布。
5. 博客发生手工修改时返回版本冲突；中台重新读取后由使用者决定如何合并。
6. 密钥泄漏或中台下线时独立撤销，不改变站长密码，不删除历史文章与来源关系。

### 第一版契约范围

| 项目 | 计划约定 |
| --- | --- |
| 入口 | 同域名 `/api/v1/`，与公开匿名读取、作者会话接口分开 |
| 身份 | 每个集成独立 Bearer 密钥，数据库只保存验证摘要，支持有效期、轮换和撤销 |
| 权限 | `articles:read`、`articles:write`、`articles:publish`、`media:write`；不开放站点设置与账号管理 |
| 资源边界 | 默认仅管理该集成映射的文章；文章来源命名空间使用不变的 integration ID |
| 外部编号 | 稳定外部编号 upsert 与数据库唯一约束，密钥轮换不改变文章归属 |
| 版本 | 返回 ETag/revision，更新与发布携带 If-Match；过期版本 412、缺少必要条件 428 |
| 幂等 | 同一集成内按操作、键和请求摘要记录结果；同键不同参数 409；默认保存 24 小时 |
| 内容 | Markdown 为主，标题/摘要/分类/标签/封面及来源规范化；草稿默认，不隐式发布 |
| 图片 | 第一版仅上传真实文件并返回本地媒体 URL，不服务端抓取任意远程地址 |
| 可观测性 | 统一错误码、request_id、分页、限流、脱敏调用记录和可定位的失败信息 |
| 文档 | OpenAPI、示例、权限说明、升级与冲突处理指南，示例由隔离测试验证 |

第一版不做第三方平台分发器、外部登录 OAuth 授权平台、任意远程素材采集、自动内容合并或公开注册。Webhook 和定时发布留作后续能力，避免首版依赖额外队列和复杂后台任务。

### 实施工作包

B0 冻结与 A 共用的文章/版本/鉴权契约；B1 集成及密钥持久化与权限；B2 来源映射及受限文章接口；B3 幂等/冲突/并发事务；B4 媒体上传与统一错误；B5 工作台集成页面与调用记录；B6 OpenAPI 和可执行接入示例；B7 撤销、跨集成访问、重试、手工改文与备份恢复验收。

## 5. 共同的数据和身份约定

- 公开 `articles` 表保留已发布快照，工作副本由单独记录承接；发布在一个事务中提升工作副本。作者和机器都不能通过普通“保存”绕过发布权限。
- 每篇文章拥有并发版本；工作台与集成使用同一检查。公开文章更新时间与 SEO 元信息仅随公开内容改变。
- 会话主体是站长，集成主体是 integration。`/api/studio/*` 使用会话与 CSRF；`/api/v1/*` 使用集成密钥，Cookie 不能代替机器凭据。
- 集成管理页调用浏览器专用管理接口；集成密钥无权创建更多密钥或修改站长。
- 相同文章来源标识与一次请求的幂等键是两个机制：前者长期识别文章，后者在保留期内重放请求结果。
- 分类、标签、附件和文章变更的失败必须具备一致结果；上传孤立媒体的清理策略由明确的保留规则处理。

### 关键异常行为

| 情形 | 用户/调用方看到的行为 |
| --- | --- |
| 中文标题未填写 slug | 生成非空、唯一、稳定地址；旧文章不重新生成 slug |
| 写作时断网或会话过期 | 正文保留，显示未保存状态；重新登录后按版本条件重试 |
| 编辑已发布文章只点保存 | 工作副本更新，公开文章和公开更新时间保持不变 |
| 两个标签页同时编辑 | 后保存者得到冲突，保留其输入供人工比较 |
| 外部文章 slug 与已有本地文章重复 | 返回明确冲突，不绑定或覆盖无关文章 |
| 中台超时重试相同请求 | 返回已记录结果，不重复创建或发布 |
| 密钥轮换或撤销 | 轮换后仍识别原来源文章；撤销凭据立即不能继续调用 |

## 6. 多 agent 实施顺序与文件归属

最初规划阶段由多 agent 生成规划与视觉讨论材料；后续已授权实施，按以下依赖推进：

1. 主 agent 冻结路由、文章 service、revision、会话和错误响应契约；完成数据库变更与兼容策略评审。
2. 身份/初始化 agent 与工作台框架 agent 并行；后者使用已冻结的接口 fixture。文章 service 由单一 agent 维护。
3. 编辑器 agent 与管理模块 agent 在不同目录并行，后台 service 所有者处理接口接线。
4. A 的共享基础稳定后，B 的集成鉴权 agent、API/幂等 agent、集成 UI/文档 agent 并行；DAO/schema 与文章 service 不允许多人同时改写。
5. QA agent 独立编写隔离浏览器、接口和升级测试；主 agent 合并审查、完整测试、容器验收并更新真实完成状态。

可先并行完成 B 的 OpenAPI/契约用例和 UI 草图，但不能在共享文章语义未稳定时各写一套保存/发布逻辑。每个阶段产出可单独验证的小提交，不能以单测存在代替实际通过。

## 7. 上线、验收与回滚

在副本上备份并演练迁移，保留现有账号、文章 ID/slug、评论、媒体、主题与统计。新工作台和旧入口短期兼容，默认单服务路径全部通过后再关闭旧管理进程。回滚需要应用与对应数据快照匹配；若切回不理解新工作副本的旧版本，应停止写入并明确恢复窗口，不能让旧程序改坏新版本数据。

A 的最终演示：首次安装/已有站点登录 → 首页作者态 → 写文保存 → 发布 → 公开阅读 → 编辑已发布文章存草稿但访客内容不变 → 再发布 → 审核评论 → 更换背景 → 退出无管理权限。

B 的最终演示：创建受限集成 → 同步草稿 → 同请求重试 → 查询同一文章 → 上传封面 → 显式发布 → 本地改文 → 中台旧版本更新被拒绝 → 密钥轮换后来源不变 → 撤销立即失效。两个集成之间不能互改文章。

两项共同保留：首页背景真实显示、卡片整区跳转、嵌套链接和点赞、暗浅主题、手机阅读、文章深链接、RSS/Sitemap、已发布可见性与备份恢复回归。

## 8. 计划评审通过条件

- 两个 change 都具备 proposal、design、规格与未勾选任务，OpenSpec 严格校验通过；没有把规划完成写成实施完成。
- 同一规范的变更只有明确的负责人；B 的契约显式依赖 A，不平行复制文章服务。
- 已有管理员、文章地址与背景配置迁移策略具体可执行，回滚说明覆盖新工作副本和新来源映射。
- 所有首版能力都有成功、失败、权限与恢复的可观察验收场景；延后能力明确列出。
- 后续多 agent 写文件范围分开，schema、文章服务、认证中间件各自只由一名实现者负责。
