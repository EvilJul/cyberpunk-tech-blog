# 作者工作台界面改造实施说明（GLM 交接版）

> 日期：2026-11-10。状态：设计方案，尚未实施。
> 目标读者：接手本仓库进行界面改造的 GLM 模型及人工验收者。
> 用户要求：工作台整体观感陈旧，需要系统改善。本文是实施依据，不代表任何界面已改好，也不构成提交、部署或真实数据操作授权。

## 后续用户反馈覆盖（2026-11-10）

当前实现已按用户反馈调整：仅保留侧栏“新建文章”入口，新建与文章导航各自选中；桌面去掉重复顶栏，手机仅保留导航栏；概览及文章页不再重复创建按钮。编辑器操作位于首屏，工具栏与属性区重新排版。图片字段在地址旁直接上传并预览，头像保留裁剪、上传只更新待保存配置。以下原方案中与这些决策不一致的顶栏、新建入口和编辑器布局要求，以本段及当前 change 后续任务为准。

### 外观整页易用性补充

外观配置以用途分区呈现：背景图片、字体、形状与间距、主题颜色、特效。常用字段使用中文选择、滑块、开关及样张，不要求用户掌握 CSS 值；精确值和自定义字体仍可在对应高级输入中编辑，旧值未操作时不自动改写。主题内部标识不重复显示为文本框，名称和扩展参数收进主题信息；原始 JSON 默认折叠。预览只影响本页，公开外观仍需显式保存，不加载 WebGL 特效作为设置预览。

## 1. 任务定义与交付边界

将 `/studio` 从“基础 HTML 管理页面”改造成清晰、紧凑、适合长期写作的现代作者工作台。主线是 **内容管理 → 写作 → 保存 → 明确发布**，不是展示数据大屏。

本轮推荐交付范围：统一工作台外壳、基础组件、概览、文章列表、编辑器，以及分类、标签、评论、媒体、站点设置、外观、账号、日志、发布集成的布局与状态。登录和首次安装页只做必要的视觉一致性处理，不改认证流程。

禁止为了视觉改造顺手引入新 CMS、UI 框架、图表库、富文本编辑器、数据库迁移或新增 API。优先使用现有 React、CSS、lucide-react、路由及业务组件。没有接口依据的数据不展示；不增加虚构增长率、折线图、在线人数、任务或通知。

### 交付物

1. 可运行的工作台界面，而非静态效果图。
2. 关键交互回归与桌面、移动端截图。
3. 变更文件、实际验证结果及未验证限制的简短说明。
4. 保持读者站、文章数据、登录会话、发布与版本保护的行为兼容。

当前工作区已有 README、读者导航、探索、搜索及测试修改。实施前重新检查 `git status`、分支、diff 和目录规则，保留这些成果；不能整体回退 `App.jsx`、`index.css` 或测试文件。

## 2. 当前事实与问题诊断

依据：用户提供的 `/studio` 概览截图，以及本轮读取的源码。没有对所有工作台页面逐页做实时浏览器验收，以下其他页面诊断来自源码结构；接手时应补充实际截图。

| 已确认现状 | 依据 | 影响 |
| --- | --- | --- |
| 工作台最大宽度 1200px，位于读者背景之上 | `src/components/studio/studio.css` 的 `.studio` | 截图两侧露出读者背景，缺乏独立工作环境 |
| 十二项左右导航平铺为一排链接；发布集成按能力开关显示 | `StudioLayout.jsx` | 功能没有分组，窄屏换行且定位效率低 |
| 所有链接统一浅蓝并带下划线 | `.studio a` | 主操作、导航和普通链接看起来几乎一样 |
| 概览统计使用无布局约束的 `dl > div` | `StudioOverview.jsx` | 数字和标签沿左侧堆叠，右侧大量空白 |
| 通用 header/nav/aside/li 选择器承担大部分样式 | `studio.css` | 语义不同的子区块互相牵连，后续扩展脆弱 |
| 设置页含递归 `Fields`、预设、上传、JSON 导入导出和恢复默认 | `ManagementPages.jsx` | 功能真实存在，但缺少面向任务的分组与渐进呈现 |
| 编辑器已包含恢复、冲突、版本、上传和发布保护 | `ArticleEditor.jsx` | 不能以重写 UI 为由删去原有业务能力 |

根因判断：缺少管理端的信息架构、设计令牌和组件层级，而非单一 CSS 丢失。样式文件确实被 `StudioLayout.jsx` 导入；本文没有证据表明 Tailwind 或构建失效，不应未经诊断就把问题归因于依赖故障。

### 本次设计取舍

- 用户已明确不接受读者端主题切换，不在工作台加入另一套浅／深色切换入口。
- 读者端将分类与标签合为“探索”，属于浏览体验；后台分类和标签仍是两种不同的数据对象。后台放到同一导航分组即可，本次不合并数据模型或擅自迁移两者。
- 让编辑内容和可执行任务成为重心，减少装饰、欢迎横幅、嵌套面板和重复统计。

## 3. 推荐视觉方向：安静的内容工作室

默认使用独立的深石墨后台：不透明底色、细边界、清晰文字、少量蓝色强调。保留站点的技术气质，工作区内部不使用读者背景图片、粒子、网格、霓虹光晕和大面积毛玻璃。

这是一套确定的实施方向，不需要 GLM 再列三种风格让用户反复选择。重点在布局、对齐和状态，而不是更换配色后保留原来的信息堆积。

### 3.1 局部设计令牌

在工作台根容器定义 `--studio-*`，所有后台新样式限定在工作台范围。以下是推荐初值，最终需测量对比度：

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--studio-bg` | `#101318` | 工作区基础背景 |
| `--studio-sidebar` | `#141820` | 左侧导航 |
| `--studio-surface` | `#1B2029` | 表单、卡片 |
| `--studio-hover` | `#242C38` | 悬停、次级表面 |
| `--studio-border` | `#333E4E` | 默认边界 |
| `--studio-control-border` | `#68798E` | 需明确识别的输入控件边界 |
| `--studio-text` | `#EDF2F7` | 正文与标题 |
| `--studio-muted` | `#A5B2C3` | 辅助说明 |
| `--studio-accent` | `#85BCFF` | 链接、焦点、选中状态 |
| `--studio-primary-bg` | `#9AC8FF` | 主按钮底色 |
| `--studio-primary-text` | `#101827` | 主按钮文字 |
| `--studio-success` | `#86D5AF` | 保存成功、发布状态 |
| `--studio-warning` | `#EFC27D` | 未保存、待审核、冲突 |
| `--studio-danger` | `#FFA6AD` | 删除、错误、撤销 |

普通文字对比度至少 4.5:1；大字和必要的控件边界、焦点指示至少 3:1。状态必须有文本，不只靠颜色。不要给全部面板加阴影，层级主要由底色、间距和边界表达。

### 3.2 字体、间距、尺寸

- 使用本地可用中文系统字体栈：`'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif`。不新增网络字体请求。代码与 JSON 采用现有等宽字体或本机等宽字体。
- 页面标题 26–28px / 600；区块标题 16–18px / 600；正文、表单、导航 14px；辅助文字 12–13px；统计数字 28–32px。
- 正文行高 1.6；代码行高 1.65。避免大量 10px、11px 小字。
- 统一间距为 4、8、12、16、24、32px。页面内部通常 24–32px，卡片 20–24px，表单字段间隔 16–20px。
- 控件高度默认 40px，紧凑表格操作不低于 32px；移动触控目标至少 44×44px。
- 卡片圆角 12px，输入／按钮 8px，状态标签 6px。避免每层套一个大圆角卡片。
- 图标复用 lucide-react，导航 18–20px、按钮 16px；图标旁保留文本。纯图标操作必须有可访问名称。
- 交互过渡 120–180ms；尊重减少动效偏好，不使用页面循环动画。

## 4. 整体布局与导航

### 4.1 桌面外壳

- 工作台背景覆盖整个可视区域，去掉 `.studio` 的 1200px 外壳上限和居中留边；在内层内容区限制阅读宽度。
- 左侧固定视觉宽度 224px，右侧内容区 `min-width: 0`。导航独立滚动，底部保留账号入口。
- 主区域顶部保留 64px 高度的轻量栏：左侧当前位置，右侧“查看博客”和“写文章”。不重复堆叠“作者工作台”大标题。
- 页面标题、说明、主操作组成统一 PageHeader。每页只设一个主视觉按钮。
- 普通页面内容最大宽度建议 1280px；设置类表单 880px；编辑器可放宽到 1440px。
- 默认使用文档自然滚动，导航可 sticky；避免工作台、main、页面卡片同时出现三层滚动条。

```text
┌──────────────────┬──────────────────────────────────────────┐
│ 内容工作台       │ 概览                  查看博客  [写文章] │
│                  ├──────────────────────────────────────────┤
│ 总览             │ 工作概览                                 │
│   概览           │ 文章、草稿与站点内容一目了然。            │
│ 内容             │                                          │
│   文章           │ 文章总数    已发布    草稿    站点访问量  │
│   分类           │                                          │
│   标签           │ [继续写作 / 内容入口]                    │
│   评论           │                                          │
│   媒体           │ 分类与标签等辅助数据置于次级位置          │
│ 站点             │                                          │
│   站点设置       │                                          │
│   外观           │                                          │
│ 系统             │                                          │
│   日志           │                                          │
│   发布集成*      │                                          │
│ ──────────────── │                                          │

└──────────────────┴──────────────────────────────────────────┘
```

`*` 发布集成只在现有 capabilities 允许时显示。账号仍保留 `/studio/account`，不是新增用户管理系统。“写文章”作为主按钮，无需再与全部管理功能平铺。

### 4.2 路由与活动态

保留现有路由：`/studio`、`/studio/articles`、`/studio/editor/new`、`/studio/editor/:id`、`/studio/categories`、`/studio/tags`、`/studio/comments`、`/studio/media`、`/studio/settings`、`/studio/appearance`、`/studio/account`、`/studio/logs`、`/studio/integrations`。

- 编辑器归属“文章”导航活动态，概览只在精确根路由选中。
- 活动项同时使用底色、文字权重和标记；不依赖下划线或颜色一种方式。
- “查看博客”是真实链接；是否新标签打开沿用既有行为，不自动改变。
- 不新增看似可点击却没有实际目标的通知铃铛、全局搜索、帮助中心或账号下拉选项。
- 带查询参数的草稿入口继续有效；刷新和直接访问子页面正常。

### 4.3 响应式

| 宽度 | 布局约定 |
| --- | --- |
| ≥1200px | 224px 侧栏；主区 padding 32px；概览四列统计 |
| 768–1199px | 200px 侧栏；padding 24px；统计两列；编辑器属性区可折叠 |
| <768px | 顶栏“菜单”打开导航抽屉；主区 padding 16px；统计两列，极窄时单列 |

移动导航抽屉需支持 Esc、关闭按钮、焦点约束与触发焦点恢复；点击导航后关闭。编辑器移动端改为编辑／预览切换及可展开属性区，不压缩为三个窄栏。宽表格只在表格容器内滚动，整页不能横向溢出。不得把所有导航简单换行塞在首屏。

## 5. 逐页改善规格

### 5.1 概览 `/studio`

目标：进入后知道当前内容规模，并能一步开始写作或查看草稿。

- PageHeader：“工作概览”，简短说明；主操作“写文章”。
- 第一行四张等权重统计：文章总数、已发布、草稿、站点访问量。每张显示标签、真实值、简短口径提示或可用的跳转。没有下钻能力的数据不伪装成按钮。
- 分类、标签数量放在下方“内容组织”小区域，或作为文章管理入口的辅助文字，避免六项大卡片同权重。
- 第二行“开始创作”操作区：写文章、查看草稿、审核评论；主次层级明确，不再用中点连接裸链接。
- 可选“最近编辑”列表仅在核对现有接口支持更新时间与正确排序后实现。若接口不足，本轮不增加，概览不需要靠假列表填满屏幕。
- 已有概览字段为 `articles/published/drafts/categories/tags/views`（来自当前前端消费字段）。`views` 的后端统计口径接手时必须核对，不能改称“独立访客”或“今日访问”。
- 未加载用骨架／占位，失败用可重试错误区；加载失败不能用 0 冒充真实值。一个真实 0 可以展示，不要写增长箭头。

### 5.2 文章管理 `/studio/articles`

- 标题与“写文章”在同一行。
- 一行工具区：标题搜索、提交／清除、状态筛选。保留现有提交式搜索，不悄悄改成全新搜索语义。
- 桌面结构化列表：标题、状态、作者／分类／标签、发布时间、操作。无支持的更新时间列不添加。
- 标题为首要内容，版本与工作副本提示为次要信息。“已发布”和“有未发布修改”可以同时表达，不能误导成修改已公开。
- 行内主要操作“编辑”，删除放次级危险入口；每个删除操作带文章名称确认，保留不可撤销及评论受影响的说明。
- 禁止新增未实现的批量发布、批量删除、排序和拖动排序。
- 移动端转换为纵向条目，元数据换行，操作保留，不缩成难读的小表格。
- 搜索和状态变化回第一页；空列表与筛选无结果使用不同文案；删除末页最后一条后需检查页码反馈。

### 5.3 编辑器 `/studio/editor/*`（最高风险页面）

桌面布局：顶部操作栏 + 中央写作区 + 280–320px 文章属性区。正文空间优先；不足以三栏时，预览采用切换，不强行并列。

- 标题输入独立且醒目；正文工具栏按标题／文本／列表／插入分组，避免一长排同等按钮。
- 保存、预览、发布／撤回层级清楚。“保存草稿”与“发布到公开站点”明确分开。
- 固定或 sticky 操作条不能遮住正文和键盘焦点，移动端考虑安全区。
- 属性区组织作者、文章地址、摘要、分类、标签及当前已经支持的字段；高级属性可折叠，但不删除字段。
- 状态区区分：未保存、本机恢复已保存但服务端未保存、服务端草稿已保存、保存中、保存后又有新输入、发布成功、冲突。不能笼统统一显示“已保存”。
- 保留当前 Markdown 能力、选区插入、图片粘贴／拖拽／文件上传、失败保留输入与预览渲染。具体已有能力以组件和测试核对，不新增富文本编辑器。
- 本机恢复置为独立提示：恢复到编辑区、导出、丢弃。不得自动覆盖服务端，也不得隐藏恢复副本。
- 冲突区显示输入已保留；比较最新版本、重载、另存新草稿保持可用。默认不覆盖、不静默重试写入。
- 离开、关闭、返回博客和浏览历史都要保留未保存保护。
- 已发布文章地址变更的确认、保存期间继续输入保护、上传期间继续输入保护全部保留。
- 不引入服务端自动保存或自动发布。当前本机恢复不是服务端自动保存，不能改名造成误解。

### 5.4 分类与标签管理

导航同归“内容”组，保持两套现有路由与后端实体。采用相同的“列表 + 新增／编辑区域”布局：

- 大区块标题明确当前管理的是分类还是标签；名称、别名及现有其他字段保留。
- 列表呈现名称、别名、当前可用的文章数和编辑／删除；没有数量字段时不造数量。
- 新增按钮打开内联编辑区或受控弹层，编辑模式明确显示“正在编辑：名称”，取消后恢复新增状态。
- 删除确认说明文章保留；不要写成会删除文章，也不要把分类删除等同于标签删除。
- 重名、请求失败保留输入并显示字段／表单错误。

### 5.5 评论审核

- 状态筛选放顶部，保留现有分页；未获数据支持的数量不显示。
- 评论卡片包括作者、时间、状态、正文及现有文章关联，操作集中在卡片底部或右侧。
- 通过、拒绝和删除使用不同层级；删除必须说明会影响全部后代回复。
- 已有祖先审核决定子树公开可见性的规则不改变。不因某条子评论自身 approved 就承诺一定公开。
- 长评论可展开，默认仍应能理解待审核内容；不能仅把正文藏在 tooltip 中。

### 5.6 媒体库

- 顶部上传区 + 响应式缩略图网格；每项展示真实解码图片、文件名及接口已有元数据。
- 点击可查看预览；复制地址与 Markdown 按钮有明确完成／失败反馈。
- 当前首版媒体管理不提供作者删除，改造不得添加失效垃圾桶按钮或接上未经授权的删除接口。
- 上传中、格式／大小错误、解码失败使用可见状态；保留成功项，不整页清空。
- 长文件名换行，等比例缩略图不得冒充原图裁切结果。

### 5.7 站点设置

将已有字段按用途排版：基本信息、作者资料、阅读布局、联系信息、高级配置。

- 标签与输入明确关联，说明靠近字段；布尔值使用一致开关或原生 checkbox 样式，不给所有字段都套巨大卡片。
- 头像裁剪、取消、上传失败和“上传后仍需保存设置”语义保留。
- 底部统一保存操作区；只有显式保存成功才显示成功。不要让折叠分组造成未渲染字段在提交时丢失。
- JSON 导入导出与高级 JSON 编辑置于折叠的“高级配置”，保持未知扩展键往返兼容；导入仍是待保存配置，不冒充已经生效。
- “恢复默认”放独立危险区域，描述实际影响范围。必须先核对当前设置重置与主题重置的不同提交行为，不为了统一样式而把二者改成相同逻辑。

### 5.8 外观

与站点设置使用同一表单系统，按预设、颜色、字体、背景、效果、圆角／现有其他配置分组。

- 明确这些是“读者站外观”，不影响后台自身配色。
- 改主题、背景上传、套预设继续遵循当前待保存与生效行为；实时预览若需新增状态或新窗口通信，列为后续功能，不假装已有。
- 图片上传与遮罩参数、默认值、主题 JSON 兼容和保留站点非主题字段全部保留。
- 未知扩展配置不能因为改写字段渲染器被删除。可留在高级 JSON 区，不需要给每个未知对象强造漂亮控件。
- 不新增读者或后台主题切换按钮。

### 5.9 账号

简洁安全设置页：当前账号信息、修改密码表单、影响说明。

- 沿用现有密码规则、autocomplete 与表单提交契约，不以视觉任务修改校验门槛。
- 说明修改密码会撤销所有会话；成功后按原认证流程返回登录。
- 密码不预填、不记录、不出现在 toast 或截图材料中；错误不清空所有非敏感上下文。
- 退出登录失败可见且可重试，不能先显示成功再吞掉网络错误。

### 5.10 日志

- 级别／现有筛选、日志列表、分页和清空操作形成清晰层级。
- 时间、级别、消息分列或对齐；长消息自动换行，详情可展开。
- 日志默认正文等宽，状态有文字；清空在危险操作区域保留确认。
- 保持后端脱敏，前端不展示未脱敏备份，不增加自动全量刷新或无分页日志加载。

### 5.11 发布集成

- capabilities 决定入口及可执行行为，不绕过默认关闭状态。
- 按集成信息、权限范围、密钥、接入说明、调用审计分区。
- 一次性密钥突出“仅展示一次”，复制失败反馈明确；不使用真实密钥作为截图数据。
- 保留轮换、撤销、权限范围、筛选及分页，不将危险操作做成无需确认的图标。
- 不在 URL、localStorage、日志、文档或埋点保存明文密钥。

### 5.12 登录、首次安装及权限状态

- 登录、setup 使用相同令牌与控件风格，但不强制显示受保护侧栏。
- 保留登录回跳、空库一次性 token、已有账户阻止重复首装等行为。
- 验证会话中、会话失败、非管理员、会话失效都提供独立可读状态；不得先闪现后台敏感内容再重定向。

## 6. 公共组件及样式工程约定

建议按需提取，而不是先建完整组件库：

| 建议组件 | 职责 | 约束 |
| --- | --- | --- |
| `StudioShell` 或现有 Layout 内部分区 | 导航、顶栏、内容边界 | 保留认证与 Outlet 逻辑 |
| `StudioPageHeader` | 标题、说明、主操作 | 不把所有操作都做主按钮 |
| `StudioButton` / 局部样式类 | primary、secondary、ghost、danger | 保留 button/link 真实语义，原生 disabled |
| `StudioField` | label、说明、错误 | 不接管业务数据校验契约 |
| `StudioNotice` | 成功、错误、警告、状态 | 错误用 alert；非紧急完成反馈用 status |
| `StudioEmptyState` | 无内容、无结果、下一步 | 不把错误渲染为空列表 |
| `StudioDialog` | 焦点、Esc、取消、危险确认 | 可复用原生 dialog；不替换为不支持键盘的 div |
| `StudioPager` / 现有 Pager | 页码、总数、按钮 | 保留现有接口页码／offset 语义 |

- CSS 使用 `.studio-shell`、`.studio-sidebar`、`.studio-page-header`、`.studio-field` 等明确职责类名。逐步替换 `.studio header`、`.studio nav`、`.studio aside` 等宽泛规则，不叠加越来越多特异性补丁。
- 后台令牌不引用可被读者主题覆盖的 `--theme-*`；使用明确字体和不透明表面阻隔读者主题。允许保留现有主题 Provider，不必重写全站配置架构。
- 核对 `src/index.css` 的 body 背景伪元素、全局链接与 main 标题规则：后台要局部覆盖，不能删全局规则破坏读者站。退出后台后不得残留 body 锁滚动、背景遮挡或主题属性。
- `ManagementPages.jsx` 同时包含多页业务。允许小范围提取布局组件；避免为换样式重写所有请求、业务 hooks 和字段转换。
- 保持现有受控输入、稳定 key 与组件挂载关系，避免重排 JSX 导致输入失焦或恢复数据丢失。
- 新增或修改函数、方法、局部函数、匿名回调按仓库规则添加简洁中文用途注释。无关代码不批量补注释。

## 7. 业务与安全不可退化项

这些是当前实现已有的边界，不是建议新增的功能：

1. 管理浏览器请求继续通过 `studioApi` 及同源会话；Cookie、内存 CSRF 和写请求校验保持。不改回 localStorage JWT。
2. 文章写入保留强版本条件 `If-Match`、revision 与 409/412 冲突处理；不移除条件头来“修复”保存失败。
3. 保存只改变工作副本；显式发布才更新公开快照。重排按钮不能变成 blur 自动发布、切换 tab 发布或提交整个表单时顺便发布。
4. 保留本机恢复按账号／文章隔离、迟到请求不覆盖新输入、导航保护、slug 变化确认。
5. capabilities 仍由服务器决定；隐藏按钮不代替服务端权限，禁止前端伪造启用状态。
6. 不修改既有用户、文章、分类标签、评论、上传、settings 和数据库作为美化样例。验收使用隔离 fixture。
7. `/blog/` 前缀下，导航、API、上传、登录回跳和图片路径均正确；使用现有工具处理地址，不硬编码根路径。
8. 保留工作台 `noindex,nofollow`、登录校验和失败重试。退出、改密码与会话撤销行为不变。
9. 原生确认如改成自定义弹窗，必须保持取消路径、危险影响文案和未保存保护，不能只保留漂亮外观。
