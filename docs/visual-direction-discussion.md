# 首页第一印象：三种视觉方向讨论

> 状态：讨论稿，尚未获用户选定。仅讨论 idea3 的布局、配色、字体、背景与动效；不属于 idea1、idea2 的实施计划。此次仅编写本文档，无源码、配置、业务数据变更，无提交。

## 当前依据与边界

已阅读 `src/App.jsx`、`src/index.css`、`src/themes/ThemeProvider.jsx`、文章列表/卡片和侧栏组件，查看 `test-results/homepage-background-fixed.png`。截图是已有验收材料，不代表本轮实时浏览器验证。知识图谱工具未能提供有效结果，故使用明确文件路径阅读。

当前首页是顶部导航、左侧搜索与分类筛选/文章列表、右侧作者/统计/分类/标签。桌面侧栏宽 320px；移动端侧栏落在文章列表之后。卡片含标题、摘要、日期、分类、标签、字数/阅读时长和阅读/喜欢数据。正文已有 Markdown 排版与目录、代码块等样式。

背景自定义是真实能力：主题支持图片、尺寸、位置、重复和遮罩透明度。当前 CSS 用固定伪元素承载背景及遮罩；近期修复通过文档底色、`body` 层叠隔离及根内容层级保持长页面背景绘制。任何后续视觉方案都应保留这些修复，不重置已保存图片与参数，也不把用户图片替换成设计示例图。本文未重新验证长页滚动。

### 视觉弱点与功能问题应分开

- 截图中导航较像工具栏，缺少站名与导航的层级；搜索和分类先于文章出现，作者/统计面板与正文争夺注意力。
- 大面积相近的深蓝圆角面板使文章、个人介绍、分类拥有接近的视觉权重。标题字号较克制、单行截断，容易让元信息先被看到。
- 背景个性很强，但与内容结合主要依靠整体压暗；可通过局部内容底色保护阅读，给外围留出更多画面。
- 截图仅一篇测试文章，左侧空白不能直接证明布局有错。摘要出现 Markdown 图片语法属于内容呈现问题，应另行诊断，不能用换配色解决。
- 搜索、分类、主题切换是已有功能；入口是否生效属于功能验收。这里讨论其位置与外观，不推断功能缺失。

“第一眼好看”“背景可自定义”“点进文章后顺畅阅读”分别评价。首页可以有气氛，进入文章后应直接看到标题与正文，不再被重复的大幅展示区挡住；这是一层直达阅读体验，不增加中间页面。

## 三种方向总览

| 方向 | 第一眼感受 | 首页重心 | 背景角色 | 主要代价 |
| --- | --- | --- | --- | --- |
| A 夜色阅读室（推荐） | 安静、精确、有暖色辨识度 | 文章标题与摘要 | 可见的环境 | 惊艳程度较克制 |
| B 浅色技术刊物 | 明朗、编辑感、留白鲜明 | 字体层级与文章列表 | 页边画面 | 对喜爱深色沉浸的用户吸引力较弱 |
| C 背景画廊 | 私人空间、画面记忆强 | 小型背景展示区接文章 | 首屏主角之一 | 最依赖图片质量和裁切，移动端更难兼顾 |

三者不采用整站紫色玻璃，也不增加伪终端、命令行欢迎语或装饰性仪表盘。不新增项目展示、内容模型、知识图谱等产品功能。

## A：夜色阅读室——让技术文章成为主角

### 首页层级与布局

桌面内容宽约 1120–1200px。64–72px 顶栏中站名单独加重，导航居中偏左，右侧放搜索和现有浅/深色按钮。下方用现有站点描述形成一段短介绍，控制在约 80–120px 高，随后进入文章区，不做满屏大标题。

文章列约占 72%，侧栏约占 28%。搜索与分类作为紧凑工具区排在列表上方；第一篇文章标题是内容区最强视觉点。作者信息保留头像和简介，统计缩成一条低强调信息；分类与标签使用分隔线和间距组织，减少层层套卡片。尊重现有左侧/右侧/隐藏侧栏配置。

### 颜色、字体与组件

- 建议底色 `#111417`、阅读面 `#1B2025`、主文字 `#ECEAE4`、次文字 `#ADB5BC`、强调色 `#D9B56D`。这是待验证色板，不宣称已通过对比度验收。
- 中文用系统黑体优先的无衬线组合；标题 24–28px、摘要 16px、辅助信息 13–14px。等宽字体仅用于代码与少量数字。
- 文章卡片采用 8–12px 圆角、单条细边、不持续发光；标题最多两行，摘要两行。日期/分类置于标题下方，数据置于最末行。移动端允许自然增高，不挤成一行。
- 搜索用完整实底输入框；分类选中项是暖色小面积填充，其余为文字加细边。按钮有文字、清晰焦点和明确选中态，不只靠颜色表达。
- 背景保留在列间及页面外缘；正文使用足够实的阅读面。先调整内容底色，避免为了配色而覆盖用户遮罩参数。

### 阅读与动效

文章页正文建议约 42–46em 宽，17–18px、行高 1.8 左右；标题、摘要/日期、正文依次展开。目录视觉从属正文，代码块与正文有明确底色区分。

桌面仅用约 160ms 的边框/颜色变化，悬停最多上移 2px；首屏可一次淡入，不做逐卡长延迟。移动端无跟手粒子、无悬停依赖，首篇文章尽量出现在首屏。减少动态效果时取消位移与淡入，保留静态背景、焦点和选中状态。

## B：浅色技术刊物——用排版形成辨识度

### 首页层级与布局

桌面约 1040–1120px，先看到站名与一句现有简介，再看到“文章”区与搜索。以宽文章列表为主，窄侧栏放作者和分类；每篇以细横线分隔，弱化卡片容器。整体更像有编辑秩序的刊物，而非深色面板集合。

标题 28–32px、摘要 16–17px，文章上下间距约 28px。分类使用带下划线的文字项，标签轻描淡写；统计降为侧栏文字行。顶部约 76px 高，以站名和底部细线构成识别。

### 颜色、字体与组件

暖白 `#F3F0E8`、纸面 `#FFFDF7`、墨色 `#242B2B`、次文字 `#596564`、深青强调 `#24665D`。正文无衬线；标题可试系统宋体形成编辑感，也提供全黑体备选，避免中文字体缺失时版式变化过大。

背景图片继续保留；中央浅色阅读面必须足够实，图片通过两侧和页头留白显露。明亮或复杂图片也不直接置于正文之下。搜索用矩形浅底和清晰边框，按钮约 4–6px 圆角，当前页导航使用线条与字重双重强调。

### 阅读与动效

正文约 40–44em 宽，18px、行高 1.85，标题与引文用排版区分，不依赖发光。桌面主要是 120–160ms 的颜色变化，无卡片浮起和持续动画。移动端单列、侧栏内容后置，站名与操作分成两行也可，不强塞微小按钮；减少动态效果时所有变化即时呈现。

选择这一路线意味着主动减弱赛博氛围。深色对应版本应保留刊物排版与细线结构，而非切回厚重玻璃卡片；背景数据始终保留。

## C：背景画廊——把自定义画面变成记忆点

### 首页层级与布局

桌面首部约 240–320px 的画面区域，占首屏约三分之一，站名及现有描述靠下放在局部实底/渐变保护区；导航拥有独立底色。画面下接文章列表，首篇标题应在常见桌面首屏可见。无需新增封面字段，使用现有背景。

文章区回到连续、稳定的阅读底板，卡片圆角约 12px，间距 20px；作者与统计压缩为侧栏轻面板。避免整屏图片再叠整屏半透明卡片，使画面与文字各有空间。

### 颜色、字体与组件

底色 `#121A20`、阅读面 `#202B33`、主字 `#F0F3F1`、次字 `#B6C2C6`，青绿 `#6BC6BA` 仅用于链接与活动状态。字体选无衬线，展示标题 36–44px，卡片标题 24px；不从每张背景自动抽色，以免普通图片使按钮对比度失控。

图片保持已有位置、尺寸与重复设置；上述展示区是视觉构图建议，不能默默把全页背景改为局部图或修改保存参数。后续需先讨论如何用内容底板遮挡下半部、让背景自然只在上方显露。没有图片时以纯色和少量静态细线完成构图，不生成替代图片。

### 阅读与动效

进入文章页取消首页展示区，保留边缘背景；正文 17–18px、行高 1.8，采用实底阅读面。桌面可以有一次 200–300ms 文字淡入，不做视差或背景持续缩放，避免重新引入背景层叠问题。

移动端画面缩至约 160–200px；文字固定放在安全底板上，避免压住人物脸部。此处不能保证任意图片都裁切理想，应以用户真实背景讨论。关闭跟手效果；减少动态效果时完全静态，背景图片与内容保持正常可见。

## 共同的阅读底线与后续评审方式

这些是选定方向后的验收建议，本轮未执行：

1. 用同一组真实文章和同一张已保存背景比较三种静态构图；同时看无背景、高亮背景、复杂背景，不靠换素材制造差异。
2. 桌面 1440px、移动 390px 及窄屏 320px 对比；长中文标题、多个标签时不挤压正文，不产生页面横向滚动。
3. 阅读优先级为标题 → 摘要 → 日期/分类 → 互动数据；空列表也不让侧栏统计成为唯一视觉主角。
4. 验证普通正文对比度至少 4.5:1，大字号至少 3:1；输入、选中、悬停与键盘焦点均检查，禁止透明度叠加后凭感觉判读。
5. 滚动长首页及长文章到底部，返回顶部、切换主题后检查完整背景与底色；确认已保存图片和各项参数未改变。
6. 移动触控区域建议至少 44px；无悬停也能识别文章入口。系统减少动态效果时不播放背景特效、闪烁、位移和持续渐变。

## 建议与需要讨论的审美选择

**根据用户已明确的“第一眼视觉效果”目标，建议优先讨论 C 背景画廊。** 首页让站名、简介和背景形成明确构图，文章页采用克制的阅读排版；A 夜色阅读室保留为更稳重的备选，B 适合偏爱纸面刊物感的选择。此建议不代表用户已选定，也不授权实施。下一步宜用同一张现有背景与同一组文章制作 A/C 的桌面和手机对照稿，先确定视觉方向再创建第三个 change。

供主代理与用户逐项讨论：

- 更希望访客先记住“文章与作者”，还是“这张背景营造的空间”？前者优先 A/B，后者优先 C。
- 深色暖金、浅色深青、深色青绿，哪组更像自己的站？偏好更安静还是更鲜明？
- 标题希望有宋体刊物感，还是全部无衬线的利落感？
- 背景希望在页面两侧持续可见，还是集中在首屏更完整地展示？能接受多少阅读底板覆盖？
- 作者卡与文章列表，谁应在第一眼更突出？能否接受把统计和重复分类降为轻量文字？
- 动效选择完全静态，还是一次轻淡入加短暂交互反馈？不建议选择持续粒子和大幅跟手作为默认风格。

先确认整体方向，再讨论明暗、强调色与背景露出比例；无需把三套视觉语言混在同一首页。
