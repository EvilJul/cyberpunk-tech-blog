## Context

依据 `docs/optimization-guide.md` 全部 37 项问题建立六个能力规格；指南描述不等同于当前代码审计结论。项目为 React/Vite、Express 双服务和 better-sqlite3；现有 npm test 是占位命令，根目录 smoke 脚本被忽略，不能作为新克隆的可靠验收入口。主规格尚未建立。

## Goals / Non-Goals

**Goals:** 覆盖全部问题编号，形成按依赖实施、可验收、可回滚的计划；安全修复和草稿隔离先行。

**Non-Goals:** 不自动部署、不操作真实业务数据；不引入完整 SSR 框架、不重写管理端为另一前端框架；数学公式不是本期强制能力。

## Decisions

1. **权限在服务端形成闭环。** 移除 Basic 分支，路由与代理校验 JWT/admin；匿名登录与原子首次初始化单独放行。管理默认回环绑定与 CORS 白名单只是附加边界。相比仅限制监听地址，服务端鉴权覆盖内部代理和误配置场景。角色与用户状态从可信服务端来源确认。
2. **统一数据和兼容接口。** 新建 stats DAO、article_stats、site_stats 与点赞去重表，事务递增并启用外键；稳定来源标识采用受信代理配置下 IP 的加盐摘要，不保存原始 IP。相比纯内存去重，SQLite 唯一约束可覆盖重启与并发。默认点赞无时间失效，按文章生命周期清理；限流为可配置策略。JSON 只作迁移输入，保留迁移版本标记；非法或孤立项输出审计报告并中止待处理，不静默丢弃。
3. **URL 是阅读状态来源。** 使用兼容当前 React 的路由方案，以 slug 加载详情，category/tag 由 URL 驱动筛选；保留 VITE_BASE_PATH。API 和资源先于 HTML 回退，错误处理最后。设置仅一处轮询。相比 state-only 视图，支持分享和历史导航。
4. **内容安全放在渲染边界。** 标准 GFM 渲染与清洗链复用标题 AST 生成目录和稳定唯一 ID，禁用原始不可信 HTML；评论存规范文本并由 UI 转义，避免存储转义后重复编码。代码高亮允许的 class 需与清洗白名单协调。图片预览具备对话框键盘行为，动态效果尊重减少动画设置。
5. **日志与匿名遥测分离。** 管理日志查询清空仅管理员；匿名错误入口单独做体积、字段、频率控制，输出结构化日志，客户端去重防抖且不上报上报失败。避免直接向现有需 token 的日志接口循环发送。
6. **稳定代理与管理模块。** 保留原上游响应契约及分页，管理客户端同步适配；10 秒 AbortController 超时、非 JSON 原样透传，网络失败 502。上传复用一个业务实现。仅抽取静态 CSS/JS，不引入管理前端框架，以降低回归范围。
7. **SEO 输出覆盖原始响应。** 配置 SITE_URL 作为可信 canonical 基址，Express 对文章 HTML 注入转义后的元信息，客户端导航同步更新。相比只使用客户端 head 库，非 JS 分享爬虫也可读取。RSS、Sitemap 仅发布数据，优先复用发布可见性查询；不把不存在的分类页面写进地图。
8. **故障退出和一致备份。** 共用幂等关闭流程；致命异常记录后非零退出，由运行器重启，不吞异常继续运行。在线备份写临时文件、完整性校验后原子重命名。宿主机使用 systemd timer/cron，容器提供独立日备份任务和同卷恢复说明。
9. **交付策略。** 仅哈希资源长缓存；HTML 与非哈希文件可验证缓存，压缩协商避免重复压缩。默认启用安全头，CSP 先清点真实资源再列白名单，不整体永久关闭。容器分离 public/admin 进程并共享持久卷，管理容器监听容器网卡但 Compose 只向宿主回环发布；本机默认仍监听回环。构建基镜像版本实现时按 package engines 验证，不照抄指南 Node 22 Alpine 示例。

## Risks / Trade-offs

- [指南与现状可能偏离] → 每个任务先用知识图谱定位并复核；已修复项记录证据，补缺失验收。
- [统一鉴权可能中断后台] → 同步改造登录与 token 携带，验证过期、普通角色和上传。
- [迁移后回退旧代码造成计数分叉] → 发布前备份；回退前停止写入，从 SQLite 导出兼容 JSON 或恢复同一时点快照，并明确窗口内恢复损失。
- [IP 去重可能合并 NAT 用户] → 文档说明限制，可信代理清单不可任意信任转发头；后续可扩展签名访客标识。
- [主题、Markdown 和 CSP 互相影响] → 明暗主题、脚本载荷及 WebGL/字体加载联合验证。
- [大范围任务难以一次审阅] → 按下述任务分阶段提交，每阶段通过后推进，应用文档不等于实现已完成。

## Migration Plan

1. 在一次性副本上复核指南、建立可提交的测试入口并记录基线；首批权限修复同时包含草稿隔离。
2. 先实现导航及数据迁移/聚合，再落地依赖这些能力的阅读和 SEO；全过程保留旧 ID。
3. 停止统计写入，在线备份 SQLite 与保存 JSON；执行事务迁移并核对计数、外键与重跑幂等，再切换唯一数据源。
4. 完成内容与管理回归后开启生产缓存、安全头和容器方案；按备份恢复演练、健康检查及回环访问验收。
5. 回滚使用已验证的应用版本及对应数据快照/逆向统计导出；不自动删除迁移源文件或在在线库上尝试降级。
