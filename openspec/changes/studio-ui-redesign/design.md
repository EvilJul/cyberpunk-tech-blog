# Design: studio-ui-redesign

> 2026-11-10 用户追加反馈覆盖：桌面不再保留全局顶栏；移动端保留紧凑导航栏。创建入口仅保留侧栏“新建文章”，取消概览、文章管理及顶栏重复按钮；新建页独立选中，已有文章编辑归属“文章”。编辑器保存／预览／发布首屏可见，工具栏紧凑；文章列表内容、时间、操作分区且不得被通用 CSS 覆盖内距。所有图片字段旁直接提供上传与预览，头像仍先裁剪，上传只改变待保存配置。下文相关旧要求由本段替代，业务与安全边界保持。


## Context

`/studio` 是同源 React 工作台（`src/components/studio/`），当前样式集中在 `studio.css`：`.studio` 限宽 1200px 居中悬浮于读者背景之上，导航平铺一排，通用 `header/nav/aside/li` 选择器承担大部分样式。业务层（`studioApi.js` 的 Cookie 会话 + CSRF + `If-Match` 版本条件、草稿/发布分离、本机恢复、冲突处理）已完成验收且不在本次改动范围。

实施依据为 `docs/studio-ui-redesign-glm.md`：确定方向为"安静的内容工作室"（深石墨、不透明底、细边界、少量蓝色强调），不提供多风格候选。当前工作区已有读者端修改（README、导航、探索、搜索及测试），实施前需核对 `git status` 并保留。

关键现状文件：`StudioLayout.jsx`（认证+导航+能力开关）、`StudioOverview.jsx`（消费 `articles/published/drafts/categories/tags/views` 字段）、`ArticleManager.jsx`、`ArticleEditor.jsx`（业务保护最密集）、`ManagementPages.jsx`（分类/标签/评论/媒体/设置/外观/账号/日志共用一文件）、`IntegrationsPage.jsx`、`src/index.css` 与 `ThemeProvider.jsx`（读者主题边界）。

## Goals / Non-Goals

**Goals:**

- 工作台拥有独立、不透明的界面外壳，与读者站视觉完全隔离。
- 分组导航 + 顶栏 + PageHeader 的稳定信息架构，桌面/平板/手机三档可用。
- 概览、文章列表、编辑器及全部管理页在同一组件与令牌体系下重排，层级清晰。
- 可访问性达标：对比度、键盘全流程、焦点管理、触控目标、状态不只靠颜色。
- 所有既有业务行为（认证、版本条件、恢复、冲突、显式发布、子路径、noindex）零退化。

**Non-Goals:**

- 不引入 UI 框架、图表库、富文本编辑器、新依赖、新 API 或数据库迁移。
- 不新增读者端或后台主题切换；不改读者站外观。
- 不合并分类与标签的数据模型；不新增批量操作、自动保存、自动发布、实时预览。
- 不改认证流程；登录/setup 仅做视觉一致性。
- 不展示无接口依据的数据（增长率、折线图、最近编辑列表——除非核对接口支持）。

## Decisions

### D1: 局部 CSS 设计令牌，不换样式技术栈

在工作台根容器定义 `--studio-*` 令牌（背景/表面/边界/文字/强调/状态），所有新样式限定 `studio` 范围并用职责类名（`.studio-shell`、`.studio-sidebar`、`.studio-page-header`）。**备选**：改用 Tailwind 工具类或 CSS-in-JS——被否决，因为会引入构建/依赖变化并波及读者站；现有 `studio.css` 单文件方案只需约束命名即可承载。
令牌不引用 `--theme-*`，配合不透明表面阻隔读者主题；`index.css` 的全局规则只做后台局部覆盖，不删除。

### D2: 全屏外壳 + 内层限宽，替换 1200px 容器

去掉 `.studio` 的 max-width 与居中留边，外壳占满视口；左侧 224px 固定侧栏（<768px 转抽屉），主区内部再按页面类型限宽（普通 1280px / 表单 880px / 编辑器 1440px）。**备选**：保留居中容器只改配色——被否决，两侧露出读者背景的问题无法靠配色解决。

### D3: 渐进提取公共组件，不先建组件库

按页面改造需要逐步提取 `StudioPageHeader`、按钮/字段/提示/空态/弹窗/分页等，优先做成轻组件或局部样式类；保留 `button`/`a` 真实语义与原生 disabled。弹窗可复用原生 `dialog`。**备选**：一次性建立完整组件库——被否决，多数页面只需布局与样式统一，先建库会推迟可见交付且增加返工面。

### D4: ManagementPages.jsx 串行小改，不整体重写

该文件承载八类页面业务，重写风险高。允许小范围提取布局组件（分组表单、危险操作区），但请求逻辑、hooks 与字段转换不动；多 agent 并行时该文件必须串行持有。**备选**：先按页拆文件再改样式——拆分本身即高风险大 diff，超出本轮视觉改造边界。

### D5: 编辑器只重排呈现层，业务保护由单一实现者持有

`ArticleEditor.jsx` 的恢复、冲突、上传、选区插入、未保存导航保护、slug 变更确认等逻辑保持原 hooks 与请求路径，仅调整 JSX 层级、工具栏分组与属性区组织。该文件由单一实现者串行实施并独立评审，避免并行覆盖保护逻辑。

### D6: 移动抽屉用受控弹层实现焦点管理

<768px 顶栏"菜单"打开导航抽屉：Esc 关闭、关闭按钮、焦点约束（focus trap）、触发焦点恢复、点击导航后关闭。可基于原生 `dialog` 或等价受控实现，不引入焦点管理依赖。

### D7: 测试更新定位器而非断言

DOM 结构变化后，更新 `tests/*` 中的定位器，优先 role、label、可访问名称，不用元素序号；验证的实际行为断言全部保留（保存/发布分离、冲突、恢复、子路径、会话）。不通过删断言让测试通过。

## Risks / Trade-offs

- [风险] `ManagementPages.jsx` 单文件体量大，样式改造 diff 复杂 → 缓解：串行修改、按页小步提交、每步跑对应测试。
- [风险] 编辑器重排导致恢复/冲突等保护逻辑意外退化 → 缓解：D5 单一实现者 + 独立评审 + 验收矩阵中的编辑器专项回归。
- [风险] 后台样式经 `index.css` 全局规则泄漏到读者站，或退出后台残留锁滚动/遮罩 → 缓解：令牌与类名全部限定 studio 范围；验收矩阵含"返回读者站无污染"场景。
- [风险] 测试定位器批量失效 → 缓解：D7 约定 + 每阶段运行相关测试文件。
- [风险] 视觉改造顺手改变提交语义（如 blur 自动发布）→ 缓解：规格中的"业务行为不退化"需求作为硬约束，评审逐条核对。
- [取舍] 不做概览"最近编辑"等增值模块，除非核对接口支持——避免假数据；首版界面信息密度低于理想值，以真实能力为界。

## Migration Plan

按 `docs/studio-ui-redesign-glm.md` 第 8 节阶段推进：A 骨架（令牌/外壳/侧栏/顶栏/PageHeader/抽屉）→ B 概览与文章 → C 编辑器 → D 其余管理页 → E 集成交付。每阶段在 1440×900 与 390×844 实看后再进入下一阶段。

不涉及 API、数据库或数据迁移；回滚即还原前端源码改动（git 层面），读者站与后端不受影响。停止于可审查改动，无发布授权不提交、不部署。

## Open Questions

- 概览"最近编辑"列表：需核对现有接口是否提供可靠的更新时间与排序字段；不足则本轮不做。
- `views` 统计的后端口径：实施概览前核对（`/api/stats/views` 相关实现），确保标签文案与口径一致，不得改称"独立访客"。
- 设置页"恢复默认"与主题重置的既有提交行为差异：实施 5.7 前核对，确认两者保持各自原有逻辑。
